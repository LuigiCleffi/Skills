# Step 6. Map the Attributes to Value "Themes"

Customers care about what features do for them, not the features. For each unique attribute, state the benefit it enables and then the value: that benefit expressed against a goal the customer is trying to achieve. Then cluster the value points the way customers would group them, until you have one to four value themes. Positioning puts the few things that make you special front and center; it does not showcase every loved feature.

## Feature, benefit, value

- **Feature**: something the product does or has.
- **Benefit**: what the feature enables for customers.
- **Value**: how that benefit maps to a goal the customer is trying to achieve, ideally quantified.

| Feature | Benefit | Value (customer goal) |
|---|---|---|
| Waterproof stitching on a hiking boot | Feet stay dry in streams and rain | Multi-day treks without blisters or carrying spare boots |
| Bank-feed reconciliation | Transactions match automatically | Month-end close in two days instead of eight, so the CFO reports on time |
| Bilingual consultants | Workshops run in the client's language | Plant-floor staff in two countries adopt the new process at once |

(Dunford illustrates the same three columns with consumer and B2B rows of her own.)

- One feature can produce several value points; a combination of features can produce value none of them delivers alone.
- Some consumer categories have trained buyers to translate features themselves (megapixels mean photo quality). Most products do not get that luxury.

## The "so what?" ladder

State the feature, then keep asking what it lets the customer do:

1. Feature: a patented matching algorithm. So what?
2. Benefit: faster response times. So what?
3. Value: agents answer customers while they are still on the call instead of calling back, cutting resolution time and raising satisfaction.

Stop when the answer is a goal the buyer already has and would put in their own plan or KPI.

## Cluster into themes

- Group value points that would naturally be related in the customer's mind, not in your architecture. Example: "works on any mobile device" and "works offline" both serve teams in remote locations with patchy connectivity, so the theme becomes "supports remote environments".
- Target one to four value clusters. A single theme is common and fine.
- Retire attributes whose value nobody cares about; they stay in product docs, not in positioning.
- Who cares about each theme, and how many of them exist, is the next step.

## Worked example

HVAC dispatch SaaS:

| Attribute | Benefit | Value | Theme |
|---|---|---|---|
| Auto-routing to nearest qualified tech | Tech assigned in under a minute | Win the emergency job before the caller dials the next contractor | Win every emergency call |
| After-hours answering with triage | No missed night calls | Capture high-margin after-hours revenue without a night dispatcher | Win every emergency call |
| Live location and skill tags | Dispatcher sees who can go now | Fewer wrong-tech callbacks and repeat visits | First-time fix |
| Offline mobile app | Works in basements | Techs close jobs on site, no paperwork at night | First-time fix |
| 20-minute onboarding | Techs productive day one | Add seasonal techs without training cost | (dropped: retention-level, folded into proof) |

Two themes: "win every emergency call" and "fix it the first time".

## Workflow

1. Take the attribute inventory from [Step 5](../UniqueAttributes/uniqueAttributes.md).
2. For each attribute write the benefit, then run the "so what?" ladder to customer-goal value; quantify where data exists.
3. Attach proof to each value point (customer metrics, quotes, reviews, benchmarks).
4. Cluster value points as best customers would group them; name each cluster in their language.
5. Reduce to one to four themes; park the rest.
6. Hand the themes to [Step 7](../WhoCaresALot/whoCaresALot.md) to find who cares most.
7. Later, use the themes as message pillars and as the value section of the sales story.

## Red flags

- Copy that lists features or specs with no stated outcome.
- Value statements that are generic ("save time", "boost productivity") with no customer goal or number.
- Seven or more "key benefits" or pillars.
- Themes organized by product module rather than customer goal.
- Value claims with no proof attached.
- Every feature loved by some customer forced into the message.
